# Rellio Scripture Library Application

Rellio is a full-stack web application for comprehensive, AI-assisted scripture study across multiple religious texts.

## Run & Operate

**Environment Variables:**
- **Firebase (Frontend):** `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID`, `VITE_FIREBASE_APPLE_ENABLED`
- **Firebase (Backend):** `FIREBASE_ADMIN_PROJECT_ID`, `FIREBASE_ADMIN_CLIENT_EMAIL`, `FIREBASE_ADMIN_PRIVATE_KEY`
- **SMTP Email:** `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`, `APP_URL`
- **SendGrid (Fallback):** `SENDGRID_API_KEY`, `SENDGRID_FROM_EMAIL`, `SENDGRID_SENDER_NAME`
- **General:** `EMAIL_PROVIDER` (defaults to SMTP)
- **AI Models (central config):** `SCHOLAR_MODEL` (Gemini model for the in-book Scholar, default `gemini-2.5-flash`), `SCHOLAR_MAX_TOKENS` (in-book answer length ceiling, default `2000`), `ASK_MODEL` (Gemini model for the grounded Ask/home-chat pipeline, flagged by `ASK_GROUNDED`), `ASK_MAX_TOKENS` (grounded Ask answer length ceiling, default `1800`), `EMBEDDING_MODEL` (Gemini embedding model for the scripture vector store, default `gemini-embedding-001`, reduced to 768 dims). `GEMINI_API_KEY` is required for the in-book Scholar and for embeddings.

**Scripture vector store (Scholar Engine — powers the grounded Ask pipeline via `searchScripture`, flagged by `ASK_GROUNDED`):**
- One-time bootstrap (creates the pgvector extension, `scripture_chunks` table, and indexes — drizzle-kit cannot do this): `npx tsx scripts/setup-pgvector.ts`
- Ingest a tradition (currently the Quran only): `npx tsx scripts/ingest-scriptures.ts quran` (idempotent; `--force` re-embeds, `--max-surah N` limits the range). Embeds the `en.asad` English translation per ayah into namespace `quran:en.asad`.
- Retrieval helper `searchScripture()` lives in `lib/retrieval/search.ts` and is consumed by the grounded Ask pipeline (`server/services/askGrounding.ts`) when `ASK_GROUNDED` is on.

## Stack

- **Frontend:** React, TypeScript, Tailwind CSS, shadcn/ui, Radix UI, TanStack Query, Wouter, Vite
- **Backend:** Node.js, Express.js, TypeScript
- **Database:** PostgreSQL (Neon Database), Drizzle ORM
- **AI:** Gemini (Google AI Studio — in-book Scholar via `SCHOLAR_MODEL`), OpenAI GPT-4o (other chat paths), xAI Grok-2 (fallback for non-Scholar paths), ElevenLabs
- **Session Management:** `connect-pg-simple` (PostgreSQL sessions)
- **External APIs:** `bible-api.com`, `alquran.cloud`, `sefaria.org`, `fawazahmed0/hadith-api`

## Architecture decisions

- **Guest-first Identity:** Users can explore content and features without immediate sign-up, with data persisting in `localStorage` and merging upon authentication.
- **Domain-First Structure:** Backend organized into `domains` (e.g., `auth`, `scriptures`, `chat`) for modularity and scalability, with a `/api/v1` route group for new features.
- **Hybrid Authentication:** Uses Firebase for primary email/password, Google, and Apple sign-in, with a legacy backend OTP system as a fallback.
- **Responsive Routing:** The root route `/` dynamically renders `DesktopWorkspaceHome` on wide screens and `LandingPage` on mobile.
- **Contextual AI Personas:** AI chatbot personas activate based on the religious text being studied (e.g., Islamic Mufti for Quran, Christian Priest for Bible).
- **Central Model Config:** AI model selection lives in one env-driven module (`server/config/models.ts`). The in-book Scholar is generated by Gemini via `SCHOLAR_MODEL` through a single central client wrapper (`server/services/scholarModel.ts`), with an explicit error (no silent cross-provider fallback) on Gemini failure.
- **Rolling In-Book Memory:** The in-book Scholar keeps the last 3 verbatim turns plus a running summary of older turns (folded in via Gemini, persisted per session in storage), replacing the previous fixed 5-message window so long sessions retain earlier context.
- **Scholar Engine Caching:** A 3-layer in-memory cache (`server/services/engineCache.ts`) flagged by `ENGINE_CACHE` (default ON dev, OFF prod): (1) `embedText` embeddings cached permanently (static corpus); (2) retrieved `GroundedContext` cached with TTL — in-book caches a summary-free base and re-applies the conversation summary fresh on hit, Ask keys on mode+sources+traditions; (3) full in-book answers cached per (scholarId, book+chapter, normalized-question), so a repeat identical question skips grounding + generation. `ENGINE_CACHE_BYPASS` (dev) skips reads but still writes (recompute + refresh). When the flag is off every path recomputes exactly as before.

## Product

- **Multi-Religious Scripture Library:** Access to Bible, Quran, Torah, Bhagavad Gita, Tripitaka, and Hadith collections.
- **AI Chatbot & Guidance:** Contextual AI discussions with religious texts, featuring specialized scholar personas and voice-first interaction.
- **Interactive Reading Experience:** Dynamic navigation, verse actions (highlight, note, bookmark), and reading progress tracking.
- **Personalized Home Dashboard:** Displays active reading sessions, progress stats, challenges, saved content, and personalized recommendations based on onboarding.
- **Scoped Scripture Comparison:** Dedicated feature (`/compare`) for multi-tradition text comparison with AI-powered analysis and structured results.
- **Desktop Workspace:** A 3-column IDE-like experience for chat, scripture browsing, and source selection.

## User preferences

Preferred communication style: Simple, everyday language.

## Gotchas

- **Firebase Configuration:** Ensure all required `VITE_FIREBASE_*` and `FIREBASE_ADMIN_*` environment variables are set for Firebase features to work correctly, including authorized domains in Firebase Console.
- **Email Delivery:** SMTP is the primary email mechanism. Verify `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS` are correctly set. SendGrid is a fallback.
- **Legacy Routes:** `/api/*` routes are shims; new feature work should target `/api/v1/*`.
- **TypeScript Strict Mode:** `strict: false` is currently set for the server to avoid pre-existing client-side TS violations. A full `strict: true` refactor is planned.
- **Onboarding Guard:** New users or those who haven't completed onboarding will be redirected to `/onboarding`.
